The toolkit that makes
N-ATLaS easy to build with.

natlas-kit is a Python & TypeScript SDK and CLI for NCAIR's N-ATLaS language and speech models. Unified backends, reliable structured output, Nigerian-language tasks, speech-to-text and an eval harness, in the language you already use.

View on GitHub Quickstart
The gap

N-ATLaS is powerful. Building on it isn't.

Every team re-solves the same four problems before writing a single line of their product. natlas-kit solves them once, for everyone.

1

No hosted API

You self-host. natlas-kit speaks TGI, vLLM/OpenAI-compatible and a mock backend out of the box.

2

Tricky templating

N-ATLaS uses a dated Llama-3 chat header that's easy to get wrong. natlas-kit builds it for you.

3

No structured output

Chat models don't reliably return JSON. extract() parses, repairs, validates and retries.

4

Scattered ASR

The speech models are separate repos. One ASRClient ties voice to the rest of the toolkit.

What you get

Everything you need to ship on N-ATLaS.

🔌 Unified backends

One client for TGI (Hugging Face Inference Endpoints), vLLM / OpenAI-compatible servers, and an offline mock for tests and CI.

🧩 Structured JSON

Turn free text into validated JSON with a tiny schema. Parsing, repair, type-coercion and retry are handled for you.

🗣️ Nigerian-language tasks

Ready helpers for translate, detect-language, classify and summarize across English, Hausa, Igbo, Yoruba and Pidgin.

🎙️ Speech-to-text

An ASR client for the N-ATLaS speech models, so voice-first apps go from microphone to structured data in one toolkit.

📊 Eval harness

Measure your integration on the real model, prove it works and catch regressions in CI with natlas eval.

🐍 Python & TypeScript

The same API in both ecosystems, so web, React Native and ML teams can all build on N-ATLaS without leaving their stack.

Quickstart

Three lines to your first call.

python
# pip install git+https://github.com/nevodesigns/natlas-kit.git
from natlaskit import NatlasClient, extract

nat = NatlasClient.from_env()   # any N-ATLaS endpoint
nat.ask("Translate 'good morning' into Yoruba")
# -> "Ẹ kaaro"

extract(nat, "Sold 2 brake pads for 15k to Musa on credit", {
  "item":   {"type": "string", "required": True},
  "amount": {"type": "number", "required": True},
  "on_credit": {"type": "boolean", "default": False},
})
# -> {"item":"brake pads","amount":15000,"on_credit":true}
typescript
// git clone + npm install (not yet on npm)
import { NatlasClient, extract } from "natlas-kit";

const nat = NatlasClient.fromEnv();

await nat.ask("Translate 'good morning' into Hausa");

await extract(nat, "Paid 6k for fuel today", {
  category: { type: "string", required: true },
  amount:   { type: "number", required: true },
});
// -> { category: "fuel", amount: 6000 }

Beta tested, in the open

Three outside developers. Nine real bugs, fixed.

Before this submission, natlas-kit was handed to developers outside the core team with no instruction beyond "break it." Every issue they found, and what was done about it, is public in BETA_TESTING.md, including the ones that turned out not to be bugs.

3outside testers, no core-team involvement
9 / 9confirmed issues fixed, each with a regression test
2implementations kept in parity: Python and TypeScript

Dayo

CLI-focused testing: empty input, missing and malformed arguments.

Mario

Fresh-install testing, following only the public README and website, nothing else.

Ebube

Deep edge-case testing of extract(), classify() and the retry logic, in both Python and TypeScript, with a written regression report.

  • Ebube

    The JSON scanner counted {/} inside quoted string values, breaking on text like {"note": "closing brace } inside text"}.

    Fix: both the Python and TypeScript JSON finders now track string state and ignore braces inside quotes.

  • Ebube

    Malformed-JSON repair blindly replaced ' with ", corrupting apostrophes inside already-valid strings, e.g. "O'Connor" became "O"Connor".

    Fix: replaced with a quote-aware scanner that only converts single-quote delimiters, not apostrophes inside text.

  • Ebube

    In Python, a boolean was silently accepted for a number/integer field, because bool is a subclass of int.

    Fix: validation now explicitly rejects booleans for numeric fields in both implementations.

  • Ebube

    Fractional values in an integer field were handled inconsistently between truncating, rounding and not coercing at all.

    Fix: both implementations now truncate toward zero in every case, string input, numeric input, Python and TypeScript alike.

  • Ebube

    In Python, a reply that was still malformed after repair raised a raw json.JSONDecodeError that escaped the retry loop instead of being caught.

    Fix: every JSON parse failure is now wrapped so the existing retry handling covers it.

  • Ebube

    classify() could return the wrong label when one label is a substring of another, e.g. ["in", "income"] matched "income" as "in".

    Fix: exact match is checked first, then substring matching falls back to the longest labels first.

  • Dayo

    A missing or malformed schema file raised a raw Python traceback from the CLI.

    Fix: the CLI now catches that and prints a one-line error with a non-zero exit code.

  • Dayo

    natlas ask "" and natlas extract "" silently accepted an empty prompt.

    Fix: the CLI now rejects empty input with a clear error instead of sending it to the model.

  • Mario

    pip install natlas-kit, as shown on the website and README, failed: the package wasn't published to PyPI yet.

    Fix: docs and the website now show the install that works today, pip install git+https://github.com/nevodesigns/natlas-kit.git, verified end-to-end in a clean virtualenv.

Reviewed, intentionally unchanged

classify() returning text outside the supplied labels when nothing matches at all is documented, intentional fallback behaviour, not a bug: changing it would be a breaking API change we didn't want to make without more real-world usage first. Unsupported top-level JSON types (null, an array, a bare string) already raise correctly, and a 10,000-character input was handled without error.

What this round didn't cover

No live N-ATLaS inference, no accuracy testing across Hausa, Igbo, Yoruba or Pidgin outputs, no real ASR audio testing, no live-endpoint failure modes, no concurrency testing. That evidence is tracked separately, against a live N-ATLaS deployment, see "Proven" above.
